# 2026-11-26 元数据审计基线（market-pro 选型数据核查 · 阶段 0+1）

## 背景与范围

下游 `dsh-market-pro` 的 `/market-pro` 选型对目录数据有硬依赖：其检索不是向量语义搜索，而是**词项加权匹配**（标题 45、keywords/安装目标 30、描述正文 16、分类/语言元信息 10），分类过滤是硬过滤；而 schema 4 的普通仓库行大多没有 keywords，**描述与分类就是 AI 选型的主要证据**。本次核查针对 3 万+ 已收录仓库的两个问题——描述是否新鲜、分类是否准确——先做纯本地、零 GitHub API 的阶段 0+1：冻结口径、产出基线、量化风险、排出优先级队列。

两条可重复执行的只读审计脚本已落地（git 历史取证也不需要网络）：

```sh
node scripts/audit-metadata.mjs --write               # 现状基线 + 优先级队列 → Temp/metadata-audit/
node scripts/audit-description-drift.mjs --write      # git 历史描述漂移取证 → 同目录
```

机器可读产物：[baseline-2026-11-26.json](./baseline-2026-11-26.json)（现状汇总 + 漂移总量）、[description-drift-2026-11-26.json](./description-drift-2026-11-26.json)（逐快照间隔、churn 榜、高影响清单）。大体积工作文件（`priority-queue.jsonl` 14,889 行 / 6.3 MB、`flagged-rows.jsonl`、`description-changes.jsonl` 2,335 行）留在 `Temp/metadata-audit/`，可随时用上面两条命令重建。

## 描述漂移取证（git 历史回放，95 个快照 · 2026-08-28 → 2026-11-25）

这是本次最重要的新证据：**上游描述不是准静态资产，而是高速流动的目标**。

| 指标 | 数量 |
| --- | ---: |
| 90 天内改过一次以上描述的已核准仓库 | **2,335**（占目录 7.5%） |
| 最近 30 天内改过的已核准仓库 | **1,232**（4.0%） |
| 描述变更事件总数 | 3,352 |
| 变更导致正则分类翻转的事件（regex-flip） | **855** |
| 最近 30 天有 regex-flip 且无 category override 钉住的仓库 | **236** |
| 最近 30 天描述变更的**订阅插件** | **256 / 2,960（8.6%）** |
| 最近 30 天描述变更的**精选仓库** | 51 / 300 |
| 上游已变、本地仍压 `description_overrides` 的仓库（30 天） | 24 |
| 描述从无到有（null → 有值） | 463；从有到无 8 |

节奏参考：最近每天约有 45–92 个仓库改描述，同时每日新增 300–490 个 topic 仓库。

churn 榜头部高度集中：`stardustlc666` 一个作者的插件群（dsh-email 18 次、dsh-ppt 15 次、dsh-hyperframes 14 次……大量同时在订阅+精选内）反复改写描述；`lishize20040802-rgb/dsh-deep-ptc-mode`、`fyjgtddco/dsh-sw-and-cad` 各 10 次。完整榜单见 drift JSON 的 `churning_top`。

结论：

1. **"描述是否有更新"的答案是——更新得太快，任何人工层都会持续滞后**。每日快照链路本身没问题（npm 双 registry 当前同步正常），瓶颈在上游文案变化后，分类钉、翻译层、编辑稿的失效检测。
2. 855 次 regex-flip 直接证明：**靠正则读描述定分类的结构，在上游文案漂移下天然不稳定**——哪怕描述文本没变脏，作者改写措辞就足以让仓库在类目间跳动。分类必须靠语义复审钉进 `category_overrides` 才能稳定。
3. 30 天内 8.6% 订阅插件描述变动——订阅展示层（presentation）需要机制化的 re-review 队列，而不是一次性翻译。

覆盖率缺口：**2026-11-19 重标定之后新核准的 2,522 个仓库中，只有 199 个有 category override，2,323 个完全靠正则/fallback**——重标定的语义覆盖每天都在被新增量稀释。

高影响面的交叉（队列证据）：

- 订阅插件行中带分类/描述不确定性的：**998 / 2,960**（三分之一）；

- 可安装（command）且分类多规则碰撞的：**3,668**；
- 疑似误分类实例（待 LLM 裁决）：`tw93/Mole`（76k★，fallback utilities）、`reactive-resume/reactive-resume`（agents-workflows）、`alchaincyf/huashu-design`（ui-experience 首命中）。

## 结构性修复：filterPool 描述口径不一致（阶段 0.3 结案）

**根因**：`render.mjs loadState()` 把 `description_overrides` 应用于内存快照后再做分类与渲染，而订阅索引链路（`market-shadow.mjs` / `candidates.mjs` / `expand-mappings.mjs`）直接读原始快照——同一份策展数据，两条派生路径用不同文本做正则分类。且 `candidates.mjs` 在合并阶段还会用原始快照**重新派生** entry 覆盖 shadow 行，单修 shadow 无法根治。

**修复**（2026-11-26，本仓库）：

- [scripts/market-pool.mjs](../../../scripts/market-pool.mjs)：`filterPool` 内部统一应用 `description_overrides`（成员资格、分类、返回行三处一致），新增导出 `applyDescriptionOverrides`；浅拷贝被覆盖行，不 mutate 调用方对象。
- [scripts/host-market/candidates.mjs](../../../scripts/host-market/candidates.mjs)：unique 覆盖层的再派生改用 override 生效后的快照。
- [scripts/market-shadow.mjs](../../../scripts/market-shadow.mjs)：不再需要局部处理，依赖共享层（注释注明契约）。
- 新增 [scripts/test-market-pool.mjs](../../../scripts/test-market-pool.mjs) 9 个回归测试（覆盖分类翻转、纯 override 成员资格、大小写、不可变性、wire 输出、category override 优先级）。

**影响面**（用修复前 legacy 语义对照复算，17 行）：16 个仓库分类修正（如 `hakuno410/dsh-board-bridge` utilities→agents-workflows、`wodongx123/dsh-qq-notify` ui-experience→integrations-sharing），1 个仓库 `luzhouheng/dsh-gen3d` 因 override 提供唯一可用描述而**新进入市场池**（media-vision）。这些差异将在下一次订阅索引重建时传播到 `metadata.category`——属于修复性变化，届时报告 diff 即可。不变量验证：修复后原始输入与 override 输入的池化结果**逐行一致（parity violations = 0）**，审计脚本会持续监视该不变量。
